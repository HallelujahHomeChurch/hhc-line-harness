# Architecture corrections before helper migration

The 2026-11-14 review identified three blockers. Runtime admission remains closed until the corrections and their consumer changes pass review and release verification.

1. Asset collection discovery now defaults to legacy collections and retains local ACL authorization without Account/Harness dependencies. Source discovery uses `sourcePolicyVersion=1`, independent pagination and current Account roles. Presenter merges complete listings; a retryable source failure leaves legacy choices available with an explicit incomplete notice and retry. Authentication failure is not hidden as partial success.
2. Asset change pages load metadata once and authorize at most 100 requests per Harness batch. A 500-entry page has at most five batch calls plus initial/final collection checks. Harness evaluates a batch in one database snapshot using its own source/group/publication records. Asset retains byte/deadline/destination ACL ownership. No shared database, allow cache, legacy fallback or recursive callback is introduced. Missing or malformed decisions, pause, dependency loss and revision changes do not advance cursors. Definitive per-item revocation/expiry produces tombstones.
3. Search/reset/result/edit routes normalize LINE identity rejection to 403 `search_forbidden`; upstream outages remain 503. Tests use the actual identity adapter with synthetic provider replies and verify no domain operation runs on rejection.

The private batch route is `POST /priv/source/check-batch`, protected by the existing dedicated Asset caller/token. Requests are limited to 64 KiB, responses to 16 KiB on the client, and 1–100 entries. Envelope: `{version:1,requests:[{id:"0",request:<single source-check request>}]}`. IDs must equal their decimal array indices. Response: `{version:1,decisions:[{id:"0",decision:<single source-check response>}]}` in exact order. No source bytes or credentials are included in decisions.

Release order: Asset discovery isolation, closed batch-capable Harness, then source-aware Presenter admission. Source settings/intake stay off until the complete contract is deployed and verified. Existing weekly bulletin, recording and livestream jobs retain their configuration and contracts. Presenter tags/releases, real LINE acceptance, office-proxy authenticated inference, legacy owner handoff and single-writer cutover remain separate gates. Original plan copies are unchanged.

Validation evidence is recorded separately from source implementation; local fixtures do not establish production or device acceptance.

The first independent review found two missed real paths and a cross-batch withdrawal race. Follow-up tests now cover real PostgreSQL reset/delta readers and an empty legacy listing with a reachable incomplete/retry picker. Migration 029 adds `groups.revocation_revision`; invalidation advances it atomically while leaving management and Reply revisions unchanged. Source decisions include a positive `revocationRevision`; Asset compares it before completing a page. No source decision is accepted across a completed withdrawal. This contract is deployed closed before any source admission.
