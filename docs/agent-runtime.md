# Agent runtime (local implementation)

The runtime uses one `@openai/agents` Agent factory and official `OpenAIResponsesModel` adapters. Group and direct-Admin contexts supply different strict tool sets; there are no handoffs, hosted tools, URL fetches or provider-side conversations. Replies render backend-owned evidence or management metadata, not unverified free-text claims from the model. Model selection and proposal handles must resolve to tools' scoped results.

`AGENT_ENABLED` defaults off. When enabled, API composition requires `OPENAI_API_KEY`, `OPENAI_MODEL`, `AZURE_OPENAI_ENDPOINT` (an approved Azure resource's `/openai/v1/` endpoint), `AZURE_OPENAI_DEPLOYMENT`, `AZURE_CLIENT_ID`, and separate `OPENAI_TARIFF_JSON` / `AZURE_OPENAI_TARIFF_JSON` snapshots. Each tariff contains integer micro-USD per million input, output, cached input, 30-minute cache-write and 12-hour cache-write tokens. No production credentials have been configured. Published documentation lists `gpt-6.1-terra`; deployment/account capability, quality, rates and regional availability still require authorized external acceptance.

All SDK and HTTP retries are disabled. `store:false`, disabled tracing, sensitive trace exclusion and disabled client logging are explicit. This does not claim provider zero retention. Only bounded text, strict schemas and application-owned completed tool results enter model requests. Provider response/conversation IDs, hidden reasoning and provider-specific state are discarded. Non-text content and incomplete tool calls fail closed. Tool arguments and results are encrypted product recovery data, never diagnostic logs.

Each run shares 45 seconds, 32,000 input/output tokens, four model calls and eight distinct tool invocations across providers. Before an attempt, PostgreSQL locks reserve the UTF-8 input upper bound plus protocol overhead and maximum output, using the worst configured input/cache-write price plus 20%. Taipei calendar-month ledgers include reserved/unknown costs. OpenAI exposure cannot exceed USD 500; Azure crossing USD 100 creates a deduplicated durable alert without a spending stop. Alert dispatch remains Task 10. Settlement uses detached provider usage in the original call month. Missing/invalid usage retains its reservation; missing/inconsistent cache-retention usage detail requires reconciliation. Price snapshots must match the configured model before enablement.

Only connection failures, HTTP 429/5xx and OpenAI month-budget exhaustion can switch to Azure, within the same run budget. The run then stays on Azure, even across a month boundary. Refusals, invalid arguments, authorization errors and empty retrieval do not trigger fallback. Completed model steps replay only against identical application-owned inputs and fresh authorization. Completed tools deduplicate by run, tool name and canonical validated arguments, independent of provider call IDs. A claimed step lacking a durable completion is unknown and is not replayed speculatively.

Explicit group natural-language requests enqueue an Agent job. LIFF search and explicit 搜尋/查詢 commands retain deterministic keyword search without model calls. Model failure can return freshly reauthorized keyword evidence with an explicit downgrade label. Group tools use fresh LINE membership and source revisions; ordinary reads do not call Account. Description/deletion tools return drafts only. LINE and LIFF expose a separate complete preview, followed by an explicit human confirmation through the existing SourceEdits operation.

Direct Admin natural-language requests have separate encrypted sessions/jobs, current binding and global-Admin revision checks, a 30-minute idle boundary and 24-hour ready-result retention. They expose group states/counts and model usage only. Pause/delete drafts open existing management previews; setup/resume stays in the original group confirmation flow. Background completion never sends LINE messages. Explicit result pickup uses a new Reply token and does not rerun the Agent. Reset, restore generation and stale binding invalidate previous work; delivery reservation checks session/result fences again.

Task 9 local implementation includes conversation follow-ups and the pinned embedding/index pipeline described below. Local evidence includes real SDK loops with stub models, intercepted official Responses transports, concurrent PostgreSQL budget tests, provider fallback after a completed tool, source revocation, Admin separation, reset fencing and browser preview/confirmation. No paid model, real LINE, Azure identity, deployment or device acceptance has occurred.

## Dedicated OpenAI network path

`OPENAI_PROXY_URL` optionally selects the retained private bastion-to-office CONNECT relay for OpenAI Responses and OpenAI embeddings. It accepts only an HTTP(S) origin without URL credentials, path, query or fragment. Connections permit only `https://api.openai.com:443`, retain TLS verification, reject redirects, disable SDK retries and never retry directly when the configured relay fails. Each client owns a bounded dispatcher and destroys it on shutdown. Azure fallback and Azure embeddings keep their own direct transport; LINE, Account, Asset, queue clients and process-wide proxy settings are unchanged. No Codex subscription credentials or desktop configuration are used.

Before enabling models, verify the complete deployed API/embedding-worker → bastion → office path, destination/source restrictions, and office service recovery. A running relay or a local CONNECT fixture does not establish live availability. Keep existing helper network resources until successor acceptance; the transport creates no relay service or network rule.

## Conversation and semantic index follow-through

Group follow-ups retain only up to five source IDs as an encrypted checkpoint, then reload current evidence with fresh group membership and revisions. Admin follow-ups retain a reference to their last metadata result, recheck its principal and reload current management metadata. Reset and the 30-minute idle boundary clear these references. Query jobs use a durable per-owner sequence rather than timestamp ties. Withdrawal of a question cancels its queued request; withdrawal of evidence cancels dependent runs and deletes their encrypted model/tool recovery records.

`EMBEDDING_ENABLED` is separately opt-in. `EMBEDDING_PROVIDER`, `EMBEDDING_MODEL`, `EMBEDDING_RESPONSE_MODEL`, `EMBEDDING_VERSION`, `EMBEDDING_DIMENSIONS` and `EMBEDDING_INPUT_MICROS_PER_MILLION` are mandatory, along with only the selected provider's credential. The version pins provider, request/deployment name, expected response model, dimension and chunker. Azure deployment immutability and real vector equivalence remain external acceptance obligations. There is no embedding provider fallback.

`pnpm worker:embeddings` is a separate, bounded PostgreSQL worker: UTF-8 chunks at most 2,000 bytes, four chunks per model call, one background batch per channel at a time, 45-second per-run budget, at most 100 batches / ten minutes per invocation. It yields to active query/Admin model runs. Failures retain unknown cost and retry at most hourly while the source remains current; month recovery does not rerun previous user questions. Scheduling and container limits are part of Task 10, not a deployed job. API and worker credentials remain separate from original-media workers.

pgvector is installed in `public` by migration 018; migration permissions and extension availability must be verified before deployment. The first version remains `building` until its current active-source backfill is complete and an evaluation has actually been recorded. `embedding:evaluate <cases.json>` runs 30–100 distinct scoped cases through that pinned model, charges the same budget ledger and emits a metadata report. `embedding:activate <report.json> <expected-active-version|none>` requires the recorded report checksum, >=90% top-5 and matching model/version/dimensions, then switches versions atomically. These are operator commands; running them against a real provider/environment requires external acceptance authority. No such command has been run against a real provider.

Similarity uses an exact pgvector scan over a materialized current-group set. Author/type/date restrictions and current source/revision/text-hash checks occur before the top-20 candidate limit. Keyword retrieval remains available while vectors are unavailable/building, with an explicit semantic-degradation gap. Basic search does not call a model. Real corpus scale, latency and provider quality remain acceptance work; local tests exercise synthetic vectors rather than claiming real semantic quality.

Model version proposals retain an exact live evidence quote, source IDs, producer and model-estimated confidence. They remain `candidate` in the database and UI; a model cannot mark a relation confirmed, replace an original, or infer authority from filenames/timestamps. Source withdrawal removes their evidence. Description/deletion drafts still require human preview and confirmation.


The SDK integration checks use published packages, including the real `APIConnectionError` class (its `name` is generic) and reject incomplete assistant/tool outputs. Cache-write reservations cover both 30-minute and 12-hour tariffs; settlement requires a consistent per-tier usage breakdown. Documentation reviewed for adapter assumptions: [OpenAI model documentation](https://developers.openai.com/api/docs/models/gpt-6.1-terra), [tracing behavior](https://developers.openai.com/api/docs/guides/agents/integrations-observability) and [Azure Responses API](https://learn.microsoft.com/en-us/azure/foundry/openai/how-to/responses). These sources establish documented interfaces, not this account's live capability.
